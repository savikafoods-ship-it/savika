This document is a comprehensive compilation of the entire journey. It serves as
a master playbook for building a lightning-fast (Lighthouse 90+), highly

Admin Panel in less than 7 days.

1. PRODUCT REQUIREMENTS DOCUMENT (PRD)
--------------------------------------------------------------------------------
Vision: Deliver a premium, seamless, high-performance shopping experience with 
an aesthetic UI, backed by a robust, secure, and easily manageable admin panel.

FRONTEND (STOREFRONT) CAPABILITIES:
- Dynamic Hero & Promo sections.
- Product Catalog with real-time dynamic pricing based on variant/weight selection.
- Unique "What is this?", "Health Benefits", "Culinary Uses", and "FAQs" product pages.
- Cart System (Client-side global state management using Zustand).
- Checkout Flow with Pincode auto-resolution (PostOffice API) and dynamic delivery fees.
- Payment: Fully functioning Cash on Delivery (COD) flow. UPI/Card/NetBanking 
  temporarily marked as "Coming Soon" for future integration (PhonePe/Razorpay).
- User Authentication (Login/Signup/Forgot Password).
- Customer Order Tracking Dashboard.

BACKEND (ADMIN PANEL) CAPABILITIES:
- Role-based Access Control (RLS): Only admins can access the `/admin` routes.
- Live Dashboard: Total Revenue, Orders, Products, and low-stock alerts.
- Product Management: Full CRUD operations, variant/weight-based pricing mapping, 
  and rich-text/JSON-LD metadata management.
- Image Sorting: Ability to upload, reorder, and set primary images mapped to 
  Supabase Storage Buckets.
- Order Management: Status updating (Pending -> Shipped -> Delivered) with 
  Courier tracking ID assignments.
- Customer Management: Viewing user profiles and lifetime value.

2. DESIGN GUIDELINES & AESTHETICS (UI/UX)
--------------------------------------------------------------------------------
Goal: Evoke a premium, luxury brand feeling while maintaining a Lighthouse 
Performance Score of 90+ across all metrics (LCP, CLS, INP).

- Color Palette: Rich, harmonious colors. Avoid generic raw hex codes (replace 
  standard red/blue with deep ambers #C17F24, dark slates #2E2E2E, rustic whites #F5F0E8).
- Typography: Modern, bold sans-serif fonts (e.g., Inter, Outfit, or Plus Jakarta).
- Visual Effects:
    * Glassmorphism applied sparsely on floating nav-bars and modals.
    * Subtle, buttery-smooth reveal micro-animations (`animate-in fade-in slide-in`).
    * Active hover states on all interactable elements (opacity drops, scale[0.98] clicks).
- Performance & Image Optimization (Lighthouse >= 90):
    * NO heavy third-party CDNs (Removed FontAwesome CDNs, rely on SVG/NPM packages).
    * `priority={true}` on all Above-the-Fold (ATF) hero background images.
    * Use Next.js `<Image />` component with properly defined remotePatterns in 
      `next.config.ts`.
    * Remove render-blocking renderers. Load scripts asynchronously.

--------------------------------------------------------------------------------
3. TECHNICAL REQUIREMENTS DOCUMENT (TRD)
--------------------------------------------------------------------------------
CORE STACK:
- Framework: Next.js 15+ (App Router, Server Components, Server Actions).
- Database & Auth: Supabase (PostgreSQL, Supabase Auth, Row Level Security).
- Storage: Supabase Storage Buckets (Public `products` bucket).
- Styling: Tailwind CSS.
- Forms & Validation: React Hook Form + Zod.

DATABASE SCHEMA ARCHITECTURE:
1. `profiles`: (id references auth.users) | full_name, mobile, address json, role.
2. `categories`: id, name, slug, description, created_at.
3. `products`: id, name, slug, is_active, price, stock, metadata (JSON), 
    category_id (FK), image_urls (Array).
4. `orders`: id, user_id (FK), order_number (unique hex), items (JSONB), 
    subtotal, delivery_fee, total, status, shipping_address (JSONB).
5. `coupons`: code, discount_percent, min_order_value, is_active.

ROUTING ARCHITECTURE (App Router):
- `/src/app/(storefront)`: Public layout.
- `/src/app/admin/(authenticated)`: Admin layout protected via Middleware.
- `/src/app/api/...`: Next.js Route Handlers.
- `/src/proxy.ts`: Middleware proxy handling canonical redirects.

SEARCH ENGINE OPTIMIZATION (SEO):
- Statically generated `sitemap.xml` mapping via `src/app/sitemap.ts`.
- `public/robots.txt` disallowing crawlers on `/admin` and `/checkout`.
- `export const metadata` statically mapped on every page.
- Injected `JSON-LD` schemas (`BreadcrumbList`, `Product`, `WebSite`, `Organization`).

4. THE 7-DAY DEVELOPMENT PROCESS (SMOOTH WORKFLOW)
--------------------------------------------------------------------------------
Phase 1: Database & Infrastructure (Day 1)
- Provision Supabase. Create Tables. Configure Row Level Security (RLS).
- Setup Next.js boilerplate. 
- Map `createClient` and `createServiceClient` inside `src/lib/supabase/server.ts`.

Phase 2: Authentication & Middleware (Day 2)
- Build the Next.js `src/proxy.ts` (middleware) to verify Supabase cookies.
- Lock down `/admin` routes. Route unauthenticated users back to `/auth/login`.

Phase 3: Storefront & Product Listing (Day 3 & 4)
- Build Home, Shop, and Category dynamic routes (`/product/[slug]`).
- Implement `generateStaticParams` fetching data from `createStaticClient()` 
  to ensure instant, static HTML caching (Lighthouse 90+ optimization).

Phase 4: Cart & Local Storage (Day 5)
- Integrate Zustand. Handle Add to Cart, Remove, Quantity adjustments.

Phase 5: Checkout Flow & Schema (Day 6)
- Build the Multi-step checkout. Add POST `api/orders/create` validation.
- Implement Cash on Delivery (COD) logic and UUID / Hex order tracking ID generation.
- (PhonePe/UPI setup left as `Coming Soon` until merchant keys are verified).

Phase 6: Admin Dashboard & Polish (Day 7)
- Tie the Database CRUD operations to the Admin UI.
- Run Lighthouse audits. Fix render-blocking code. Apply Google SEO configurations.

5. HURDLES, "GOTCHAS", AND HOW TO OVERCOME THEM
--------------------------------------------------------------------------------
Throughout a massive Next.js + Supabase build, you will hit these specific hurdles.
Here is exactly how to resolve them:

Hurdle 1: Supabase Images Returning HTTP 400 Errors
- Problem: The Next.js `<Image />` component fails to load Supabase public URLs.
- Solution: You must whitelist the Supabase hostname inside `next.config.ts` 
  under `images: { remotePatterns: [...] }` otherwise Next.js will block the proxy!

Hurdle 2: TypeScript / ESLint Crashing the Production Build
- Problem: Overly strict Next.js 15 type enforcement causes Vercel builds to fail.
- Solution: Temporarily bypass build-breaking lints by adding `ignoreDuringBuilds: true` 
  and `ignoreBuildErrors: true` into `next.config.ts`, but actively fix critical 
  ZodType errors (like `err.errors` inside catch blocks) by casting to `any`.

Hurdle 3: Next.js 15+ Async Route Handlers `params`
- Problem: In `api/orders/[id]/route.ts`, accessing `params.id` throws a type error.
- Solution: Next.js 15 requires you to treat `params` as a Promise. 
  `{ params }: { params: Promise<{ id: string }> }` followed by `const { id } = await params`.

Hurdle 4: Database Schema Payload Mismatches
- Problem: Inserting products from the Admin panel returns a 500 error.
- Solution: Never implicitly trust your frontend Zod schema to magically match 
  Supabase. Ensure array structures (like `image_urls`) and JSON objects 
  (`metadata`) match their exact SQL definitions. Set default values for `null`.

Hurdle 5: Dynamic API Opt-in Breaking SEO `generateStaticParams`
- Problem: Calling `cookies()` or standard `createClient()` inside layout or 
  sitemap files forces Next.js into dynamic rendering mode, preventing Google indexing.
- Solution: Build a specific `createStaticClient()` inside your Supabase 
  utilities that DOES NOT invoke cookies. Use it exclusively inside `generateStaticParams` 
  and `sitemap.ts` to guarantee static HTML.

Hurdle 6: Canonical Duplication Confusing Search Engines
- Problem: Google views `www.site.com` and `site.com` as duplicate spam content.
- Solution: Add standard 301 redirects natively inside your Middleware `src/proxy.ts` 
  to force rewrite `http` -> `https` and `non-www` -> `www` BEFORE the page renders.
  Also inject identical `canonical` meta tags to your `<head>`.

Hurdle 7: Lighthouse Performance Failures (LCP)
- Problem: Hero section loads slowly due to high-resolution background images.
- Solution: Always define `priority={true}` on Above the Fold Next.js images to 
  pre-load them. Move UI scripts (like FontAwesome or Google Analytics) to load 
  lazily inside Next.js `<Script strategy="lazyOnload">`.
